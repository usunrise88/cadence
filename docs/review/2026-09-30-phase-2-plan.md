## Interfaces between streams

### The step job (wave 0: `internal/steps`)

A pipeline step that runs on a worker is a River job of kind `step` whose args are a `steps.Spec`:

```go
type Spec struct {
    StepID, PipelineRunID, ProjectID string
    Kind, KindVersion string            // pinned by the pipeline: nemotron_finetune@1
    Params     json.RawMessage          // resolved: defaults applied, departures recorded by P
    Inputs     map[string]ArtifactRef   // name → artifact
    Outputs    map[string]string        // name → artifact type
    Resources  Resources                // gpu (bool), gpus (1, R44), memoryGb, diskGb, jobKind (training|eval|export|data)
    Priority   int                      // higher first; per project, from the project's budgets
    Estimate   *EstimateSeconds         // for availability windows (R19); nil = unknown
    Overrides  Overrides                // batchScale (OOM retry), resumeFrom (training-state artifact)
    SecretNames []string                // secret names the step kind declares; W injects values into the lease only
    Attempt    int
}
type ArtifactRef struct{ Hash, Type string; Size int64; Meta json.RawMessage }
type Outcome struct {
    State   string                      // done | failed | cancelled
    Error   *StepError                  // type: oom | step | lost (reaped) | cancelled; message; retryable
    Outputs map[string]ArtifactRef
    Metrics map[string]float64          // final values the step reports (valWer, secondsPerStep, …)
}
```

- W implements `steps.Leases` (`Await(ctx, jobID) (Outcome, error)` — blocks until the lease completes, is reaped or
  the job is cancelled) and fills it from `/worker/leases/{id}:complete`. P's `step` handler calls it; wave 0 ships a
  stub that fails with `no worker protocol` so P builds alone.
- P runs output hooks after recording outputs, in the same transaction as the step's `done` state:
  `steps.OnOutput(artifactType, func(ctx, tx, steps.Output) ([]events.Draft, error))`. D registers `dataset`, R
  registers `checkpoint` and `calibration`.
- Card slots: W's scheduler decides which queued `step` job a worker may lease (runtime has the kind, card free under
  the cap, the job kind is allowed on the card, the window fits the estimate, project priority, FIFO). One training
  slot per card; eval and data jobs may share a card's remaining memory only when `Resources.memoryGb` fits beside it.

### Worker protocol (wave 0 contract, tag `worker`)

Exempt from the vocabulary and from MCP, like `host`; Bearer `cwk_` only (one per host; `cadence admin worker-token`
writes it to `CADENCE_WORKER_TOKEN_FILE`, and a restart re-issues it like the host token).

| Operation | Path | Purpose |
| --- | --- | --- |
| `workerRegistrations.new` | `POST /worker-registrations` | At start: runtime (name, version, image digest, environment lock), step kinds with schemas, model families. Stored as registry versions; answers the worker id |
| `workerLeases.claim` | `POST /worker-leases:claim` | Long-poll (≤ 30 s) with capabilities: worker id, cards with total and free memory and utilisation. Answers a lease (spec, input URIs, card, memory cap, secret env, traceparent, heartbeat interval) or nothing |
| `workerLeases.report` | `POST /worker-leases/{id}:report` | Heartbeat every 10 s: progress, card telemetry; answers `cancel: true` when the job was cancelled or paused. Three missed beats reap the lease (`lost`) |
| `workerLogs.new` | `POST /worker-leases/{id}/worker-logs` | NDJSON lines `{t, level, msg, fields}` appended to the job's log file; tail through `job.{id}.log` |
| `workerMetrics.new` | `POST /worker-leases/{id}/worker-metrics` | Batches of points `{name, step, value, wallTime, epoch?}` → metrics table; `run.{id}.metrics` when the job belongs to a run |
| `workerLeases.release` | `POST /worker-leases/{id}:release` | Completion: outcome with the output artifact manifest (hash, type, size, meta), final metrics, or a typed error |
| `workerArtifacts.set` | `PUT /worker-artifacts/{hash}` | Upload for workers without the shared volume (remote later); the shared-volume worker writes `cas/` directly |

Artifacts in v1 live on a volume shared by the control plane and the worker (`CADENCE_CAS_DIR`, default
`/var/lib/cadence/cas`): `cas/b3/<ab>/<hash>` for a file, and for a directory artifact (Shar set, checkpoint dir) a
JSON manifest `{files: [{path, hash, size}]}` stored as a blob whose hash is the artifact's hash, each file stored as
its own blob. Writers write to `cas/tmp/` and rename. Input URIs in a lease are `cas://b3:<hash>`; the worker
materialises a directory artifact into the step's scratch directory by hard links.

### Pipelines (P)

```yaml
# pipelines/train-stage.yaml in the project repository
name: train-stage
inputs: { mix: mix, base: base_model }          # pipeline inputs by artifact type
steps:
  - id: calibrate
    kind: oomptimizer_calibrate@1
    in: { base: $inputs.base, data: $inputs.mix }
  - id: train
    kind: nemotron_finetune@1
    in: { base: $inputs.base, data: $inputs.mix, calibration: calibrate.calibration }
    params: { steps: 500 }                        # only departures from defaults are written
```

A pipeline input is an artifact reference resolved by the facade that starts the run (a mix revision renders to a
`mix` artifact with its resolved `input_cfg`; a base model version to a `base_model` artifact). Types are checked at
`dryRun` against the step kinds' `consumes`/`produces` from the published registry. Kinds that run in the control
plane itself (none in v1 besides `noop`) would use the same spec with `runtime: control-plane`.

### Data, runs, playbooks

- D: `dataset` artifact = JSON lines of utterances `{audio: b3 hash, duration, sampleRate, language, speaker?,
  text, origin}` plus a header `{source: {name, licence, kind, languages}, splits}`. The hook creates or reuses the
  Source, inserts Utterances by content hash, Transcripts with origin, and registers a `dataset_version` registry
  version whose fingerprint is the hash of the sorted utterance hashes and split assignment (R18).
- R: a run owns one pipeline run; `run.{id}.status` mirrors it; checkpoints come from the `checkpoint` hook with
  `meta: {step, valWer, family, weightsHash}`; calibration from the `calibration` hook caches seconds/step for
  (base model, card class, cap, precision, bucket config) and switches estimates to `basis: measured`.
- K: a playbook is a template version (`templateKind: playbook`); a playbook session is an agent session of kind
  `playbook` whose initial plan is the chain and whose prompt is rendered from the template.

## Decisions taken for phase 2 (owner-delegated, recorded in `07` "Open questions")

- R18 is taken as proposed: imports register a Source, Utterances, Transcripts and a fingerprinted dataset version
  through `pipelines.run` (`pipelines/import`).
- Runtime-neutral core step kinds (`echo`, `dataset_import`) ship in every runtime image; a pipeline pins
  `kind@version`, and the scheduler may lease it to any runtime that publishes the same kind, version and schema
  hash. Framework step kinds exist in one runtime only (R40 still holds for them).
- Replay (R17) at full breadth is ≈ 195 h of audio across 39 locales; the staging disk takes it, but phase 2 imports a
  capped replay sample (≈ 1 h per locale from FLEURS train) and the replay golden sets (FLEURS test ≤ 300 per
  locale); the ≈ 5 h per locale corpus is a later re-freeze of `dataset/replay-base` with the same pipeline.
