## Shared rules for every stream

- Read `CLAUDE.md` and `.claude/rules/*` first; follow the phase-0 patterns (`internal/projects`, the command
  pipeline, `problems`, handlers in `internal/server`). Spec-first: contract change → `make gen` → implement.
- Contract: add paths under your stream's marker in `api/openapi.yaml` (paths block) and schemas under your marker at
  the end of `components/schemas`; remove the `planned` entries you implement. Tags are already declared.
- Handlers go in `internal/server/handlers_<stream>.go`; domain logic in its own `internal/<concern>` package.
- Migrations are pre-numbered: A `0002_identity.sql`, B `0003_registry.sql`, C `0004_approvals_jobs.sql`
  (wave 2 takes 0005+). River's own tables come from its migrator, run at start next to ours.
- IDs are `<prefix>_<uuidv7>`: `usr_`, `crd_` (credential), `reg_` (collection), `ver_` (version), `cmp_`, `sec_`,
  `apr_`, `job_`, `aud_`. Token prefixes: `cdk_` API key, `cst_` agent session, `cwk_` worker (phase 2).
- Every new problem type gets its help article in `docs/help/errors/` (then `make help-sync`).
- Tests at the right layer: unit, then integration with testcontainers Postgres (`-tags integration`).
- Before handing back: `make gen lint test` and `make test-integration` green in your worktree; commit with
  Conventional Commits, author `-c user.name="Anton" -c user.email="rusunrise88@gmail.com"`, plus the
  Co-Authored-By and Claude-Session lines. Do not push; do not touch other streams' areas.

## Interfaces between streams

- **Actor and scope (A).** `auth.Actor` stays the contract's Actor. A adds `auth.Scope` (project id or empty for
  all, whether registry read is allowed, the permission preset name) available through `auth.ScopeFromContext`, and
  `auth.CheckProject(ctx, projectID)` for handlers. `server.Config.Actor`, when set, still attributes every request to
  that actor without authentication — tests and the other streams keep working until A merges.
- **Mint and revoke (A).** `credentials.MintAgentToken(ctx, tx, sessionID, projectID, preset) (token, id, error)`
  and `credentials.Revoke(ctx, tx, id)`; tokens are stored as SHA-256 hashes.
- **Policy (C).** `policy.Decide(ctx, policy.Input{Actor, Scope, Operation, VerbClass, ProjectID, Estimate})` →
  `allow | approval | deny` with the matching rule. The command pipeline calls it before running a command. A
  command that needs approval is stored (method, path, query, headers minus credentials, body, actor) and answered
  `202 {approvalId}`; approving replays it through the API handler as the original actor with the approval id in
  context, so `causedBy` carries it. Commands tell the pipeline their project through the context
  (`commands.WithProject`).
- **Jobs (C).** `jobs.Enqueue(ctx, tx, jobs.Spec{Kind, ProjectID, Args})` → job id, inside the caller's
  transaction; kinds register a handler at start; progress and state go out as `job.{id}` events.
- **Defaults (B).** `defaults.Get()` returns the parsed embedded `defaults/defaults.yaml`; the MCP `defaults://`
  resource and the wizard read it.
- **MCP (E).** A tool call becomes an in-process request to the API handler with the caller's `Authorization`
  header, a minted `Idempotency-Key` and `dryRun`; the result returns as JSON text content marked as data.
