## Decisions taken for phase 3 (owner-delegated, recorded in `07` "Open questions")

R20–R25 are taken as proposed. Where they leave a choice open:

1. **Baseline (R23).** The base model's existing `base_model` registry version *is* the baseline model version: the
   `baseline` alias may point at a `base_model` or a `model` version, and no second registration of the base model is
   made. A project's `baseline` alias defaults to its default base model when unset.
2. **`baselines.set`** (named in 04) is `aliases.set` with name `baseline`, which is already approval-gated; no new
   operation.
3. **Gates live in the project repository** as `gates.yaml` (versioned like recipes, editable by agents through
   commits); `gates.get|edit` read and write it through the recipes service; an eval records the file's SHA.
4. **Eval records** are a global table (registry scope, no project), keyed by `modelKey × goldenSetVersionId ×
   normalizerVersionId × decodingHash × scorer@version`. `modelKey` is the weights hash (`b3:`) for checkpoints and
   model versions, and `base:<versionId>` for a base model version (its weights are materialised by the family's
   step, so the hash is not known before the first run).
5. **The punctuation-insensitive companion score** is `werNoPunct`: the same scoring normalizer plus punctuation
   removal. When the normalizer already strips punctuation the two are equal.
6. **Base models are evaluated through a new family role `materialize`** (verb already in the vocabulary): a step that
   turns a `base_model` artifact into a `checkpoint` artifact (NeMo: `checkpoint_from_base@1`; toy: the same). Evals
   then always transcribe a `checkpoint`.
7. **Golden sets reference a dataset version.** `goldenSets.freeze` takes a frozen, eval-only dataset version and a
   normalizer version and registers `golden-set/<name>`; the 34 replay golden datasets and FLEURS he become golden
   sets by freezing them (admin approval) on the stand at the gate.

## Interfaces between streams

### Registry payloads (wave 0 schemas; G and E fill them)

```yaml
NormalizerPayload:            # normalizer/<name>, version name YYYY-MM-DD.<sha of the canonical JSON>
  locale: he-IL | "*"
  unicode: NFC | NFKC
  casefold: bool
  punctuation: keep | strip   # strip = Unicode P* categories → space
  removeMarks: bool           # combining marks (niqqud, accents) removed after decomposition
  mappings: [{from, to}]      # literal replacements applied in order after unicode, before punctuation
  numbers: keep               # phase 4 adds spoken/written conversion through the pack's ITN
GoldenSetPayload:             # golden-set/<name>
  datasetVersionId, datasetHash (b3), normalizerVersionId, locale, domain,
  utterances, hours, fingerprint, groups: call|speaker|utterance   # the bootstrap's resampling unit
ModelPayload:                 # model/<name>, from models.register
  checkpointId, weightsHash, checkpointHash (b3), familyId, baseModelVersionId, projectId,
  evalId, gate {verdict, gatesSha}, lineage {mixSha, recipeSha, datasetVersionIds[], runId}, card (markdown)
```

The `normalizer` artifact is the payload as JSON (`application/json`, `meta: {versionId}`), rendered by the control
plane like a `base_model` artifact.

### The `scores` artifact (Y writes, E reads)

A directory artifact:

- `summary.json`: `{schema: "cadence.scores/1", scorer: "wer_score@1", normalizer: {versionId}, language, utterances,
  refWords, refChars, wer, cer, werNoPunct, sub, del, ins, charErrors, buckets: [{lo, hi, utterances, refWords, wer}],
  stability?: {partialWords, unstableWords, ratio, editsPerSecond}}` — rates are fractions (0.123), not percent.
- `utterances.jsonl`: one row per utterance in dataset order: `{audio, speaker?, group, durationS, ref, hyp, refWords,
  sub, del, ins, refChars, charErrors, ops: [[op, ref, hyp]]}` with `op` one of `=`, `S`, `D`, `I` (Diff reads them).
  `group` is the bootstrap unit: the call id when the dataset has one, else the speaker, else the audio hash.

Duration buckets come from `defaults.yaml` `eval.duration_buckets_s` (`[0, 2, 5, 10, 20]`, open last bucket).

### Eval pipeline (E generates, Y's kinds run)

Per eval, one pipeline run with, for each missing cell `(model, golden set, profile, decoding)`:

```
materialize-<m>   family.roles.materialize   (only for a base model; once per model)
transcribe-<c>    family.roles.transcribe    in: {model, data: golden dataset, boost?}  params: {profile, target_lang}
score-<c>         wer_score@1                in: {hypotheses, data: golden dataset, normalizer}
```

The `scores` hook writes the eval record (key above) in the step's transaction, and E links the cell. Step kinds and
versions come from the published family descriptor (R41: Go never names them).

### Gate (E)

`gates.yaml` (defaults from `defaults.yaml` `gate.*`):

```yaml
primaryProfile: 160ms                     # R20: the gate reads this cell only
target: { goldenSets: [golden-set/fleurs-he], rule: beat-baseline }
replay: { goldenSets: [golden-set/replay-golden-*], maxRegression: 0.005 }   # 0.5 absolute WER points
deletionsInsertions: true                 # fail when deletions fall while insertions rise (target cells)
significance: { samples: 1000, level: 0.95, seed: 1 }
```

Checks: target — WER delta vs baseline < 0 with the CI's upper bound < 0; replay — fails when the delta > 0.005 and the
CI's lower bound > 0; deletions/insertions — fails when the deletion rate's CI is below zero and the insertion rate's
above. Verdict `passed | failed` with each check `passed | failed | inconclusive` and its numbers.
