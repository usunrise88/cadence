# Cadence spec — Overview: decisions, architecture, stack

_Part of the Cadence specification v0.2 (2026-09-29). Source of truth: the Claude Doc "Cadence — spec v0.2"; these files are its export, split by area. Figures referenced below live in the Doc._

## Decisions and scope

Cadence is a self-hosted workbench for the full life of Nemotron ASR fine-tunes — data, training, evaluation, export and deployment, production flywheel. Every action is an API call, and a built-in agent (Claude Code or opencode) is a first-class operator that the user watches and steers from a chat window.

| Date | Decision | Why |

| 2026-09-29 | The MCP server (Streamable HTTP at `/mcp`, official Go SDK) holds no logic of its own: a tool call is an in-process request to the API handler with the caller's `Authorization`, an `Idempotency-Key` derived from the MCP session and JSON-RPC id (sessionless: the client's tool-use id), and `Cadence-Tool-Call-Id` recorded as `causedBy.toolCallId`; results are JSON `{data, note}` marked as data, problems are tool errors naming their help article, `/mcp` answers 401 exactly when the API would | One path for authorisation, validation, idempotency and audit whether the client is the UI, the CLI or an agent; a client's retry replays instead of acting twice |
| 2026-09-29 | Floating-window snapping moves through Dockview's public `transformFloatingGroupDrag` hook; internals (the overlay) only for resize snapping, keyboard moves and focus yielding. | 2026-09-29 | Theme steps where the Theming table fails its own contrast rule: focus ring indigo-9 (dark: indigo-10), active sash slate-9, warning text amber-12; floating overlays are `border-box` | Spike S3 contrast script: indigo-8 is 2.3:1 on slate-1, slate-8 1.9:1, amber-11 4.498:1. | 2026-09-29 | Agent-native and API-first: one OpenAPI contract; UI, agents (through MCP) and CLI are equal clients | Nothing the UI can do is out of an agent's reach, and the reverse |
| 2026-09-29 | Target model: `nvidia/nemotron-3.5-asr-streaming-0.6b`, pinned by Hugging Face revision and tracked as an entity | Latest Nemotron ASR (released 2026-06-04); upstream updates become explicit, not silent |

| 2026-09-29 | Processes are pipelines of typed step kinds in a worker registry; API, MCP tools and a generic panel derive from each step's schema | A new or changed step touches one module, nothing else |
| 2026-09-29 | Projects are the unit of work: own repository and worktrees, budgets, gates, workspaces; reusable assets live in the registry (below) | Several languages and clients in flight at once without interference |

| 2026-09-29 | Monorepo (Go control plane, SPA, Python worker, TypeScript agent host) shipped as one docker compose | One version, one CI, one deploy on the staging host |

| 2026-09-29 | Two roles in v1: admin (the user) and reviewer — an external native speaker invited per review batch, who sees only Triage queue, Diff and Audio for assigned items, can play but not download audio, and loses access when the batch closes | Hebrew transcripts need native checks; a scoped role keeps the rest of Cadence and the raw data closed |
| 2026-09-29 | Claude Code sessions authenticate with the user's Claude subscription, as the CLI does; agent budgets for Claude are counted in turns and tokens, not money | No API key to manage; open check: confirm the subscription terms cover ACP-driven and scheduled headless sessions, else those use an API key |
| 2026-09-29 | The flywheel LLM judge is an external model (Claude or another API model); it receives only PII-redacted transcripts and dialogue context, never audio | Judgement quality over self-hosting; the redaction gate keeps call content inside |
| 2026-09-29 | Observability in v1: structured JSON-lines logs to files with rotation, OpenTelemetry traces written to a local file exporter, a Prometheus-format metrics endpoint; no Grafana stack yet | Instrumentation stays in the code so a stack can be attached later without changes |
| 2026-09-29 | Version identifiers for dataset versions, model versions and pipelines: date plus short SHA (`2026-09-29.a1b2c3d`), assigned by the system; human labels are optional aliases | Sorts by time, unique by content, no manual bumping |
| 2026-09-29 | Polygon stays a separate tool; Cadence hands over model versions through the delivery script and shares nothing else | Different lifecycle and users; a merge is not worth the coupling now |
| 2026-09-29 | Proposed defaults awaiting confirmation: call samples kept 90 days; PII masked by NER spans in the transcript and cut from the audio; secrets in a compose env file; nightly Postgres dump and content-store sync to a mount; development through WSL2 on the workstation | Recorded as defaults so work can start; change any of them here |
| 2026-09-29 | Projects are created by a wizard (name and locales, base model, agent driver and model, instructions template, repository, storage and budgets) and bootstrapped by a job; agent configuration is edited later in an Agent settings panel | No hand-assembled project directories; the opencode model question moves into the wizard |
| 2026-09-29 | A project's recipes repository can be a GitHub repository (created or linked in the wizard) or the internal bare repository | The user chooses per project; Cadence only needs a clone and a remote |
| 2026-09-29 | Reusable assets (sources, dataset versions, golden sets, normalizers, base and registered models, mounts, templates) live in a Cadence-wide registry as immutable versions; projects adopt them by reference, move aliases, and record dependencies in data.lock | The registry pattern of W&B, MLflow and DVC: share without copying, reproduce from a lockfile |
| 2026-09-29 | Every entity follows one six-step loop (prepare, check, run, review, decide, record), one document anatomy and one verb vocabulary; an entity manifest generates header, actions, states and next-step hints, and the same <entity>.<verb> name is the API operation, the MCP tool and the UI command | Consistency by construction: a user and an agent learn one way of working that holds across all five blocks |
| 2026-09-29 | Every parameter has a default, description, source and safe range in one versioned defaults.yaml; four playbooks and a smoke project ship in v1; departures from defaults are recorded on the entity | A non-expert can start with three fields; an expert sees exactly what was changed |
| 2026-09-29 | Eleven blocks from the coverage audit specified: password+TOTP admin with invitation links and scoped tokens; agent-native permission systems instead of a Cadence sandbox; versioned operations with tested backups; language packs and hot words inside the project; task and streaming metrics; stereo-aware annotation workflow; full testing pyramid; Telegram notifications with inline approvals; experiments and sweeps; a telephony augmentation profile; import and export formats. Data governance under immutability deferred | Answers of the audit review; each block placed where it is used |
| 2026-09-29 | Operation naming is mechanical: one `x-cadence.entity` per resource derives tool, path and topic spellings; HTTP shape maps to verb; items by global id, collections under projects; `auth` and `me` operations exempt; `revoke` joins the vocabulary; spec names renamed to fit (R1) | The generator refuses unknown verbs, and the spec's own tool list failed that check |
| 2026-09-29 | Agent sessions: the MCP token passes only through ACP `session/new`, never onto disk; one Unix user per session; egress through an allowlisting proxy; permission presets rendered for both agents while a server-side policy engine decides (R2–R4, R7) | A committed token would reach GitHub; agent-side rules alone cannot be trusted or enforced for opencode |
| 2026-09-29 | Three agent clocks: 5 min stuck turn, 30 min idle, approvals expire after 24 h without pausing the session; Claude uses the subscription for interactive sessions and an API key for playbook and scheduled ones until the terms are confirmed (R5, R6) | One 3-minute timeout paused every session awaiting a phone approval; the open check on subscription terms stays |
| 2026-09-29 | `baseline` is a gated alias and `production` moves only by promotion; secrets live in an encrypted file store, not the compose env file; internal repositories are bare repos served over smart HTTP (R8–R10) | `aliases.set` bypassed approvals; the UI cannot write an env file; the internal repository had no defined home |
| 2026-09-29 | `defaults.yaml` is one embedded file that step schemas reference by key; estimates come from measured seconds per step with a seeded table as fallback; mixes are project revisions with `mixes.edit`, not versions (R11–R13) | Defaults were repeated in pipelines; dry-run estimates had no model; the agent-loop gate needs an agent to edit a mix |
| 2026-09-29 | The worker leases jobs over HTTP like a CI runner, with its own credential kind; artifacts go to a BLAKE3 content-addressed store; metrics in Postgres, logs as NDJSON files (R14, R15) | River is Go-only and the worker is Python on the staging host; outputs needed a home before mounts exist |
| 2026-09-29 | Five playbooks in v1: "Fine-tune from a dataset version" joins the four; replay uses about 5 h per locale of public data frozen once as `dataset/replay-base`, gated on FLEURS test deltas against the base model; imports register Source, Utterance and Transcript; compute gets availability windows (R16–R19) | The training gate needs a playbook that runs without ingest; replay data was unspecified; the shared card needs preemption-safe runs |
| 2026-09-29 | Evaluation: the primary cell is Эра's production latency (`[56,1]` by default) and `[56,13]` replaces "offline"; the scoring normalizer is a registry asset while text style stays in the language pack; eval records are keyed by weights hash; `models.register` moves to the evaluation phase; the base model is the first baseline; boosting and augmentation are eval axes; audio is served as signed segment streams (R20–R25) | Comparable WER needs a shared scoring normalizer; checkpoints must be cached before registration; boost and robustness checks are evaluations |
| 2026-09-29 | Auxiliary models (language ID, pseudo-label ensemble) are pinned registry entries with a commercial-use licence check; annotation guidelines are versioned markdown in the project repository (R26, R27) | The starter pipeline named models that were not registry entries; help articles ship in the binary |
| 2026-09-29 | Proposed, awaiting confirmation: captured call audio kept 90 days, curated golden-set and correction audio 24 months, tombstones keep versions immutable; PII redaction gated on measured recall; parity ≤ 0.1 WER and ≥ 99.5 % identical tokens, p95 time to final ≤ chunk + 100 ms at 32 streams; Эра contract drafted in OpenAPI; promotions hash-chained and signed (R28–R33) | A golden set that expires every 90 days breaks comparability; the deployment gate had no thresholds |
| 2026-09-29 | Small fixes: a generated `cadence` CLI in the server binary; agent budget in turns and tokens; pipeline version = commit SHA; project switch moved off Ctrl/Cmd+Shift+P; `projectId` optional on events; nothing exposed outside the compose network (R34–R39) | Contradictions found in the kickoff review |
| 2026-09-29 | Claude Code sessions of every kind use the owner's Claude subscription; opencode sessions use MiniMax through its Token Plan, with the key in the agent-credentials volume (R6, owner) | The owner confirmed the subscription covers headless sessions; opencode needs a provider that may see project data, which the free Zen model of spike A1 is not |
| 2026-09-29 | Delivery follows six gated phases — Shell, Agent loop, Training, Evaluation, Data, Deploy and flywheel — with each phase's contents in the repository's `ROADMAP.md`; resolutions R1–R39 are in the Resolutions tab (`08-resolutions.md`) | A dependency audit moved each capability to the phase that first needs it |
| 2026-09-29 | Framework seams now, everything beyond them deferred (owner): step kinds name a runtime (a pinned image), models carry a family with latency profiles in milliseconds, steps after the family's role steps read neutral artifacts (Shar with audio and text only, hypotheses, analysis arrays), and a CPU toy pack runs the conformance suite in CI; training from scratch, tokenizers, multi-card runs, packs beyond NeMo (sherpa-onnx, Hugging Face, k2/icefall), external baselines and spike F1 wait without a phase (R40–R46) | Retrofitting after phase 2 means migrating checkpoints, eval records and panels that assume NeMo; the owner wants extensibility prepared, not built; NeMo can already train from scratch, and icefall would need its own PyTorch-matched k2 |
| 2026-09-29 | Models are tried by hand in a Transcription tool — a file, the microphone or an utterance span, one to three targets, blind compare, telephony simulation — through one WebSocket per session relayed to a worker job running NeMo's streaming pipeline; raw PCM up, partial and final words down in the shape streaming vendors share; nothing is stored, and the test is not an MCP tool (R47–R50) | The spec judged checkpoints only on golden sets; a person needs to hear and speak to a model; the owner: it is a manual test, no more — stored, comparable results are what evals are for |
| 2026-09-29 | Identity (phase 1): `auth`-tagged operations (`auth.get|setup|login|logout`, `totp.enroll|confirm|disable`) are not commands — no Idempotency-Key, If-Match or dryRun, and the generator exempts them; API keys act as `automation` and agent tokens as `agent` actors whose id is the credential id; a credential's scope is `{all, projectId, registryRead, preset}` checked per handler (`auth.CheckProject`, `CheckRegistryRead`, `CheckAll`); the browser session is an opaque `cws_` token in the `cadence_session` cookie, stored hashed like every other credential | Sign-in has no actor to key idempotency on and a session has no revision; one table and one resolver keep every credential revocable the same way; a registry-only key needs a scope that is neither "all" nor one project |
| 2026-09-29 | One audio view with stacked tracks (waveform, acoustic spectrogram, model input, emissions, reference and hypothesis words, streaming timeline) on a shared time axis, WebGL2 rendering, magma by default and no rainbow maps; uPlot for time series and ECharts for analytics, fed with binned numbers from the API; streaming metrics and confidence intervals follow published definitions, bootstrapped per call (R51–R54) | The spec had a waveform and three curves; ASR work is judged by listening, reading spectrograms and alignments, and comparing distributions |
| 2026-09-29 | The command pipeline asks the policy engine before every command; an approved request is replayed in-process through the API handler as its original actor, inside the approve command's transaction (a savepoint), so the replayed change, its events with `causedBy.approvalId`, the decision and the replay's answer commit together; the replay replaces the 202 stored under the original Idempotency-Key (phase 1, stream C) | One code path for every command whoever sends it; no double execution when an approve is retried; a client repeating its original request after the approval gets the real result |
| 2026-09-29 | Jobs run on River with a `jobs` mirror table the API shows; River's migrator runs at start after Cadence's SQL migrations while the same advisory lock is held; periodic chores (approval expiry, audit retention) are River periodic jobs | River gives leader election, retries and transactional enqueue; the mirror keeps the contract's job shape, revisions and `job.{id}` events independent of River's schema |
| 2026-09-30 | Project repositories (R10, phase 1 wave 2) run on the `git` binary: a bare repository per project under the data directory is the canonical copy for every repository kind (internal, a GitHub repository created with a stored token, a linked https URL), with a working clone for commits to `main`; GitHub and linked repositories get `main` mirrored after each change; smart HTTP at `/git/<slug>.git` through `git http-backend` takes API keys and agent session tokens as the basic-auth password, a pre-receive hook limits agent tokens to `session/<id>`; merges use `git merge-tree --write-tree` so a conflict writes nothing. The control-plane image moves from distroless to `debian:bookworm-slim` with git and the CA bundle, still uid 65532 | Merges, hooks and the smart protocol need real git (go-git has no three-way merge or http-backend); one canonical copy on the control plane lets agent hosts clone and push through one authenticated endpoint whatever the remote is |
| 2026-09-30 | `projects.new` takes the wizard's choices (everything but the name defaults from `defaults.yaml`), creates the project in state `bootstrapping` with its agent profile and base-model adoption, and answers `202 {jobId}`; the `projects.bootstrap` job writes the repository and marks it `active`. The agent profile is a singleton sub-resource (`agentProfile.get|edit`, `/projects/{p}/agent-profile`); draft branches from `projects.sync` are accepted or discarded with `branches.accept|revert` (session branches with `agentSessions.accept|revert`); recipe files are read with `recipes.list|get` | R1 folds `:bootstrap` into `projects.new`; a singleton keeps the spec's path while passing the naming rule; draft branches reuse the verbs drafts already have |
| 2026-09-29 | Registry core (phase 1): kinds base model, dataset version and template; the control plane assigns `YYYY-MM-DD.<first 12 hex of the sha256 of canonical content>` and a database trigger keeps frozen versions unchanged; bundled versions (base-model catalogue, fixture datasets, the templates tree) and the compute hosts of `defaults.yaml` are seeded at start; `defaults.yaml` lives at `control-plane/defaults/defaults.yaml` and policies store only departures from it; secret values are secretbox files under the data directory, and the idempotency record of `secrets.new` fingerprints a MAC of the value, never the value | Versions must be named by content, not by callers; seeding at start keeps bundled content and the registry in step without a migration per template change; a plain hash of a stored request would let a database dump test guesses of a secret |
| 2026-09-30 | Search (phase 1): the index is a projection of the outbox in Postgres (`search_documents`: 'simple' full-text over per-locale normalised text plus pg_trgm word similarity > 0.4), written by an in-process indexer with its own cursor in `event_cursors`, reloading entities by id through a registration table instead of reading event payloads; `projects.search` is `GET /projects/{p}:search` and resolves visibility from the credential before the query's scope qualifiers; saved searches are `views.list|get|set` under `me`. The `cadence <entity> <verb>` CLI is generated by `make gen` as a Go table (`internal/cli/operations.gen.go`) read by one hand-written runtime | A projection rebuilds by resetting a cursor and cannot drift from what commands committed; reloading by id makes replays harmless and keeps payloads free to change; a table plus one runtime keeps the generated code small and the CLI's behaviour testable in one place |
| 2026-09-30 | Drafts are one generic store (`drafts` table, `internal/drafts`) that every draftable kind plugs into through a small interface (lock, content at a revision, apply); a draft has its own revision, one open draft per author and entity, and accepting it writes the entity's next revision attributed to the person with `causedBy.draftId`; presence is derived from open drafts and recent direct agent edits and sent whole as `presence.changed` on the entity's topic; the web renders drafts with one shell primitive (`DraftOutline`) and open documents patch their cache from their entity topic (phase 1, mix stream) | Gate, note and language pack become draftable later without new tables or UI; a draft that cannot be accepted onto a moved-on entity is refused (412 `draft-stale`) instead of merged silently; presence as state (not a stream of heartbeats) survives reconnects and reloads |
| 2026-09-30 | Agent sessions (phase 1, wave 2): the control plane keeps the session and its transcript (`internal/sessions`, `agent_sessions`, `agent_messages` upserted by key), the agent host runs it and speaks a small protocol of its own (`hostSessions.claim|report|ask|decision`, exempt tag `host`) with a dedicated `agent_host` credential (`cah_`) the control plane writes to a shared volume at start. The session token is minted at claim; ACP permission requests are answered by the preset or become `agent_permission` approvals answered back to the host; gated commands of a session join its transcript through a pipeline hook | The host holds no state the API lacks and never touches the database; a long-poll needs no inbound port on the sandboxed host; minting at claim keeps the token out of every store; one transcript and one Approvals panel for both kinds of request |
| 2026-09-30 | The agent sandbox (R3, R4) in compose: the host runs as root only to start each session as one of 32 Unix users (cs0…cs31) in a 0700 directory with a private HOME holding a copy of the agent's login from the `agent-credentials` volume (Claude: a `claude setup-token` token; opencode: `auth.json`); git runs as that user with hooks off and the token only in its environment; the host's network is internal and its only egress is `cadence egress-proxy`, an allowlisting CONNECT proxy in the control-plane binary | One login copy per session cannot leak another session's files; a long-lived setup token avoids refresh-token rotation between copies; a proxy of our own keeps the allowlist as one visible environment variable and needs no third-party image |
| 2026-09-30 | Claude Code permission rules name MCP tools the way Claude does, `mcp__cadence__<entity>_<verb>` (spike A2); the host and server map `_<verb>` back to `.<verb>` | Rules with the dotted operation id never matched, so every Cadence call asked and was denied |
| 2026-09-30 | Agent credentials are instance-wide settings in Settings → Agents, admin only (`agentCredentials.list|get|set|verify|archive`, `agentProviders.list`; exempt tag `agentCredentials`, so never MCP tools, and the presets forbid them too): the Claude Code subscription token from `claude setup-token` and opencode providers from a catalogue (MiniMax, Anthropic, OpenAI, OpenRouter, DeepSeek, or an OpenAI-compatible custom base URL). A submitted value is sealed in the secret store's transit area under the task id; the agent host claims it through `hostCredentials.claim|report` (tag `host`), writes it 0600 into the `agent-credentials` volume in the agent's own format, acknowledges, and the control plane deletes the transit copy. Postgres keeps metadata only (agent, provider, last-four hint, set at/by, expected expiry, delivery and verification state, models, default model). The `agent-host login claude|opencode` CLI stays as the fallback and writes the same files | The owner asked to connect the agents' model accounts from the UI instead of `docker compose run … agent-host login`; values still never leave the volume path — never Postgres, logs, events, audit rows, responses or an agent context — and a host-side write keeps the agents' own file formats the only place a value lives |
| 2026-09-30 | Verb `verify` added to the vocabulary (`agentCredentials.verify`): the agent host runs a tiny real request through the agent as a sandboxed session user behind the egress proxy (Claude: `claude -p` on haiku; opencode: `opencode models <provider>` then `opencode run`) and the result, and opencode's model list, are recorded on the credential | A live check of a credential is neither `scan` (data) nor `sync` (templates): it spends a request and records a result, and later fits compute hosts, mounts and stored tokens too |
| 2026-09-30 | Preference operations are not audited: a committed `workspaces.set` (the web's layout autosave) writes no audit row; refused attempts still do (`audit.Recorded`) | The audit log is for commands someone should be able to account for; a row per window move buried them, and the workspace's own `rev` already tells saves apart |
| 2026-09-30 | The control plane sends the Cadence tools a session's preset allows (`HostStart.allowedTools`, `policy.AgentAllowed`) and the Claude driver pre-allows them with the SDK's `allowedTools` | Claude Code does not apply allow rules from a repository's `.claude/settings.json`, so every Cadence call cost a permission round trip; taking the list from the policy engine, not from a file the agent can edit, keeps the agent from widening its own rules, and the server still checks every call |
| 2026-09-30 | The egress proxy learns the allowlist dynamically: `CADENCE_EGRESS_ALLOW` stays the static base list, and every 15 s the proxy polls `egressHosts.list` (exempt tag `egress`) for the API hosts of configured providers and custom base URLs (host:port when a port is named; an IP literal only when listed exactly), keeping the last good list when the control plane is unreachable. It authenticates with its own credential kind `egress_proxy` (`cep_`), written by the control plane to `CADENCE_EGRESS_TOKEN_FILE` on an `egress-credential` volume | Adding a provider in the UI must not need a compose edit and restart; the proxy's own token reads the allowlist and nothing else, so a compromised proxy cannot claim sessions or credential writes the way the host token could |
| 2026-09-30 | Imports store audio as 16-bit PCM WAV, mono, 16 kHz, written byte for byte the same everywhere; an utterance's identity is the BLAKE3 of those bytes, and an imported dataset version's fingerprint is the hash of its sorted (utterance hash, split, transcript) tuples rather than of its payload | Dedupe and leakage checks need an identity that does not change with the importing host's codec library or with the pipeline run that imported the data; FLAC would halve the bytes but its encoder output varies across libsndfile versions |
| 2026-09-30 | An API key of one project may run agent sessions there when the admin ticks it (`scope.agentSessions`, owner's choice); the default preset's `sessions-are-for-people` still binds agents and every other key, and a project key reads its own project's audit rows | The agent evals run on the staging stand through its own agent host and accounts, so no agent credential leaves its volume; an explicit per-key opt-in instead of relaxing the rule for all automation |
| 2026-09-30 | The staging card is one RTX PRO 5000 Blackwell 48 GB (sm_120), not 96 GB; the resident vLLM service holds ≈ 24 GB, so the 24 GB training cap is memory fraction 0.5 with no headroom above it, and the compute seed and estimate table use card class `blackwell-48gb` | The host was inventoried for phase 2; the 96 GB figure came from spike A3's brief and was never measured |
| 2026-09-30 | R18 taken as proposed: before the Data phase, imports register a Source (licence from the format), Utterances by content hash, Transcripts with origin and a fingerprinted dataset version through `pipelines.run` (`pipelines/import`, the `dataset` output hook) | Phase 2's gate trains on a dataset version; the minimal entities are what fingerprint exclusion, per-utterance rows and Diff need later anyway |
| 2026-09-30 | Runtime-neutral core step kinds (`echo`, `dataset_import`) ship in every runtime image; a pipeline pins `kind@version` and the scheduler may lease a neutral kind to any runtime that publishes the same kind, version and schema hash; framework step kinds live in one runtime only (R40 holds for them) | Data steps must not depend on which framework images are installed, and one import pipeline serves every pack |

## At a glance

The Go control plane is the only owner of state; the UI, the agents and the GPU worker are all its clients.

> **Figure:** Cadence architecture · UI, control plane, agent host, GPU worker, production — see the drawing in the Claude Doc "Cadence — spec v0.2".

The agent host is an API client like the UI: it relays chat through REST and events, while the agents themselves act through MCP tools and their own git worktrees — so every agent change becomes an event that the open panels receive at once.

## Stack

A Go control plane owns state and the contract; Python does only GPU work; a small TypeScript sidecar hosts the agents, because the official ACP and agent SDKs are TypeScript-first.

| Layer | Choice | Community practice it follows |
| --- | --- | --- |
| Control plane | Go single binary with embedded SPA; PostgreSQL; content-addressed store on disk | Same shape as the earlier Cadence concept and Polygon |
| API contract | OpenAPI 3.1, spec-first; Go server stubs generated (oapi-codegen strict server); TypeScript client and TanStack Query hooks generated | One contract, generated clients, no hand-written drift |
| Jobs | River (Postgres-backed job queue for Go): priorities, retries, one training slot per card | Queue in the same database as the state it changes; no separate broker |
| Events | Transactional outbox in Postgres → in-process bus → server-sent events with `Last-Event-ID` resume | Every change and its event commit together; no lost updates |
| MCP server | Built into the control plane, Streamable HTTP transport, tools generated from OpenAPI operations with curated descriptions | Agents get the same operations as the UI |
| Agent host | TypeScript sidecar (Node or Bun) using `@agentclientprotocol/sdk`; drivers for Claude Code and opencode | ACP is JSON-RPC 2.0 over stdio with an official TypeScript SDK |
