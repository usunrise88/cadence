# internal/pipelines
The pipeline engine (docs/spec/03-pipelines-defaults.md "Pipelines and extension points", docs/review/2026-09-30-phase-2-plan.md "Pipelines", "The step job").

- **Format** (`pipeline.go`): `pipelines/<name>.yaml` — `name`, `description`, `inputs` (name → artifact type), `steps` (`id`, `kind: name@version`, `in: {input: $inputs.x | <step>.<output>}`, `params` with only departures). `Parse` is strict (unknown keys fail) and checks names, pins, wiring and cycles; `Order` is the topological order (file order breaks ties).
- **Sources** (`source.go`): `Load`/`List` read the project repository at a ref (default `main`) through `Repo` (`*repos.Store`), falling back to the bundled templates (`control-plane/templates/pipelines`). A pipeline's version is the commit that last changed its file (`template-<sha256 prefix>` for a template); `pipelines.run` takes it as `If-Match` (`*` = any). A run records the commit the file was read at.
- **Step kinds** (`kinds.go`): `RegistryKinds` reads registry versions of kind `step_kind` (collection `step-kind/<name>`, payload = `StepKindDescriptor` + `name`, `runtime`, `runtimeVersionId`, optional `estimateSeconds`), newest non-deprecated first. The worker protocol (stream W) stores them; tests use `pipelinestest.RegisterKinds`.
- **Plan** (`plan.go`, `params.go`): every kind@version is published; every consumed input is wired to an artifact of the consumed type; parameters resolve `x-cadence.defaultRef` (a `defaults.yaml` key, R11) › `x-cadence.default` › the schema default, are validated against the kind's JSON Schema (google/jsonschema-go) and a mapping `x-cadence.range`; unknown parameters and required ones without a value fail. Departures are `{param, value, default}`. The estimate sums per-step seconds (`StartInput.Estimates` from a facade, else the kind's `estimateSeconds`); GPU-hours over steps with `resources.gpu`. All problems come back as one `pipeline-invalid` with field paths.
- **Runs** (`engine.go`, `store.go`): `Start(ctx, tx, StartInput)` records `pipeline_runs` (`plr_`) and `pipeline_steps` (`pls_`), indexes the inputs (they must be in the content store) and advances: a ready step whose input hash (kind, version, resolved params, input hashes) matches a finished step of the project is `reused` (outputs copied, hooks run), otherwise it is queued as a River job of kind `step` (`steps.JobKind`, queue `steps`) with a `steps.Spec`. Step states: waiting, queued, running, done, reused, failed, skipped, cancelled; run states: running, done, failed, cancelled. Events on `pipeline_run.{id}` with the project: `pipeline_run.started`, `pipeline_run.step_changed` (payload `{pipelineRunId, runState, step}`), `pipeline_run.state_changed`.
- **The step job**: the handler waits on `steps.Leases.Await(ctx, jobID)` and applies the outcome in one transaction: outputs must match the kind's `produces` and exist in the store (`artifacts.Record`); output hooks (`steps.Hooks`) run in a savepoint — a hook error fails the step and rolls its writes back; then dependents advance. `oom` → one automatic attempt at `steps.OOMBatchScale` (`overrides.batchScale`); `lost` → one retry; anything else fails the step and the run and skips the steps that never started. `Leased(ctx, tx, jobID)` marks a step running — the worker protocol calls it when it grants the lease. `Sweep` (every minute) treats steps whose job ended without an outcome (the control plane stopped while it waited) as lost.
- **Commands**: `Cancel` (waiting steps cancelled, queued/running step jobs cancelled via `jobs.Cancel`), `Retry` (a failed or cancelled step, or every failed step, as a new attempt; the run reopens), `Wait`.

Go API for facades (runs, evals, playbooks): `Engine.Start(ctx, tx, StartInput{ProjectID, Name | Pipeline, Ref, Inputs, Params, Estimates, RunID, Actor, Priority, Fresh})` returns the run and its events; `Engine.Prepare` validates without writing (dry runs). `ListRuns(…, ListFilter{RunID})` finds a facade's pipeline runs.

`pipelinestest` runs the engine without a worker: a fake `steps.Leases` that executes `echo@1` and `tally@1` in-process with scripted failures and hangs.
