# internal/jobs
Jobs on River (`riverqueue/river`, pgx driver). `Service.Enqueue(ctx, tx, Spec{Kind, ProjectID, Args})` inserts the River job and its `jobs` mirror row (`job_<uuidv7>`) in the caller's transaction and returns the `job.{id}` event to emit. In-process kinds register a `Handler` before `Start`; the worker moves the mirror through queued → running → done | failed | cancelled, stores the result (completing the River job in the same transaction) and emits `job.state_changed` / `job.progress` on `job.{id}`. `Cancel` stops a queued job at once and asks a running one to stop. `Wait` backs `jobs.wait`. `AddPeriodic` schedules internal chores (approval expiry, audit retention) on River's leader. `MigrateRiver` runs River's own migrator under the migration lock (a `storage.Migrate` step). The `noop` kind exists for tests. Phase 2: `KindOptions.Queue` puts a kind on its own River queue (`QueueSteps` for `step` jobs, whose handlers wait for a worker); jobs carry `priority` and `pausedAt` (`SetPriority`, `SetPaused`, `Lock`) and `Progress` records progress from outside a handler (the worker protocol, `internal/workers`).
