# internal/eviction
Content-store retention (docs/spec/06-platform.md "Artifacts, metrics and logs", Retention): `artifacts.evict` deletes the blobs of superseded `training-state` artifacts once a person approved it.

- `Service.Plan(ctx, tx, Filter)` selects: every live state of a pipeline run that is `done`; of a `failed` or `cancelled` one, all but the newest (`runs.resume` continues from it); nothing of a `running` one. Kept whatever a waiting or leased step job's spec names (inputs, `overrides.resumeFrom`), a running pipeline's or an unfinished step's inputs, a registry version's payload, a checkpoint row, or another live artifact's file list (`artifact_files`), and — when `MirrorDir` is set — anything the backup mirror does not hold yet. `RunID`/`ProjectID` select whole runs; `OlderThan` and `Hashes` narrow the evictable states (`Strict`: a named hash that may not go answers `artifact-not-evictable`). Training states that stopped steps saved only into lease outcomes are indexed first (producer = the step, time = the lease's end). Blobs deleted: each artifact's own blob and a directory's files that no live artifact outside the set lists or is; `BytesFreed` counts those.
- The command (`internal/server`, handler `ArtifactsEvict`) is gated for everyone by the default preset (`store-eviction`; agents meet `agents-never-evict` first). A dry run answers the plan; the approved replay calls `Enqueue` (202 `{jobId}`).
- The job (`artifacts.evict`, 3 attempts) re-plans the hashes, marks the rows (`evicted_at`, `evicted_by`, `eviction_job_id`) and emits `artifact.evicted` on `entity.artifact.{hash}` in one transaction, then — in a second one — re-reads the rows still marked by it and the blobs no live artifact lists and deletes them (`cas.Store.Delete`), and writes an audit entry whose `detail` has the artifacts, `bytesFreed` and blobs. A retry finds the rows it already marked and deletes what is left; a second eviction finds nothing.
- Concurrency: both job transactions hold the content-store lock exclusive (`artifacts.LockExclusive`); `artifacts.Record`, a step reused by input hash and the start-time restore hold it shared (`artifacts.LockShared`) from their store check to their commit. A Record that finds the bytes between marking and deleting clears the mark and keeps them (a new directory sharing a file keeps that file); one after the deletion answers `ErrEvicted` (a reuse runs the step instead). One global lock, not one per hash: directories share file blobs, and evictions are rare and short. Lock order: the store lock before the outbox lock.
- Reference checks are index lookups (migration 0022): GIN indexes on `artifact_hashes_in(doc)` — every `b3:` hash in a document's text — for waiting/leased step job specs, running pipeline run inputs, unfinished step inputs and registry payloads, and a btree on `checkpoints.artifact_hash`.
- `Backfill` (at start) fills `artifact_files` for directory artifacts recorded before migration 0020 and clears the eviction of artifacts whose blobs verify again (copied back from the mirror).
