# internal/auxiliary
The registry kind `auxiliary` (`auxiliary/<name>`, phase 4 · stream X, R26): language classifiers, pseudo-label members and aligners. `Parse` checks a payload (the contract's `AuxiliaryPayload`: roles, licence, `outputsCommercialUse`, languages, and either `{hfRepo, revision}` or `{service: {kind, endpoint, protocol, tokenSecret}}`). `CheckAdoption` refuses a licence that forbids commercial use of the outputs (`auxiliary-licence-refused`); `projects.adopt` of an auxiliary is otherwise a registry-scope approval for everyone (preset rule `auxiliary-adoption`, matched on the `kind=auxiliary` the handler names). `Resolve` turns a step parameter marked `x-cadence.registryRef` into the version the project adopted (the pipeline engine, `internal/pipelines/registryrefs.go`, puts it in the step spec's `auxiliaries`); `CheckServices` with a `Prober` (`DialProber`: a TCP connection within 3 s) answers `auxiliary-unavailable` when a service a dry run needs does not listen. Nothing here names a model or a service: the seeds are data (`internal/registry/fixtures/auxiliaries.yaml`), and the worker pack that serves the role reads the payload.
