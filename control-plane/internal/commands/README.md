# internal/commands
The command pipeline every mutation runs through (`Pipeline.Run`): one transaction; Idempotency-Key lookup under an advisory lock on (actor, key) — same request hash replays the stored status, headers and body, anything else is `idempotency-key-reused`; the policy engine (`internal/policy`) — deny is `403 policy-denied`, approval stores the request as an approval and answers `202 {approvalId}` (a dry run runs and says `Cadence-Policy: approval`), a session-scoped approval allows; the operation's work; dry runs roll back and answer 200; outbox events with `causedBy` (command, tool call, approval); the audit row; the stored response; commit. Denied and failed attempts get their own audit row. `WithReplay` runs an approved request in a savepoint of the approve command's transaction, skipping the policy. Handlers name the command's project with `WithProject` and a spend estimate with `WithEstimate`; `HashMiddleware` keeps the request (`RequestFromContext`) and reads `Cadence-Tool-Call-Id`. One slog line and one `cadence_commands_total` increment per command. Also: request fingerprinting, `ETag`/`If-Match` parsing and revision checks.
