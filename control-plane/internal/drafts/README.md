# internal/drafts
Drafts of draftable kinds (mix now; gate, note and language pack later) and presence (docs/spec/06-platform.md "Real-time model").

A kind plugs in through `Kind` (lock/read the entity, content at a revision, apply content as the next revision). The `Store` owns the `drafts` table (`drf_<uuidv7>`, one open draft per author and entity, its own `rev` for `If-Match`), the state machine (`Transition`: open → open | accepted | reverted), the diff against the draft's base revision (`Diff`, JSON pointers), carrying a draft over to a newer revision (`Rebase`, top-level fields the draft changed win), `Save` (an agent's edit), `Accept` (the draft becomes the entity's next revision attributed to the person, cause `{draftId, draftAuthor, toolCallId}`; a moved-on entity is `412 draft-stale` with its current revision), `Revert`, and `Presence` (open drafts' authors, plus an agent's direct edit within `drafts.presence_seconds`). Events on `entity.{kind}.{id}`: `draft.created|updated|accepted|reverted` (payload `{draft}`) and `presence.changed` (payload `{presence: [...]}`, the whole list). `Policy` reads the draft policy per kind from the project's agent profile (`draftPolicy`, Agent settings), falling back to `defaults.yaml` (`drafts.mix`) for a project without a profile.
